# AWS Infrastructure via Terraform (Lesson 5)

Цей проєкт містить Terraform-конфігурацію для автоматичного розгортання базової інфраструктури в AWS (us-west-2). Інфраструктура побудована за модульним принципом, що забезпечує перевикористання коду та легке масштабування.

## 🛠️ Опис модулів

### 1. s3-backend

Відповідає за безпечне зберігання стану інфраструктури.

- S3-бакет: Зберігає файл terraform.tfstate. Обов'язково увімкнено версіонування (для можливості відкату змін) та шифрування AES256.
- DynamoDB: Використовує ключ LockID для запобігання одночасного внесення змін кількома розробниками (State Locking).

### 2. vpc

Створює ізольовану мережу в AWS:

- VPC із заданим CIDR-блоком (наприклад, 10.0.0.0/16).
- 3 Публічні підмережі (розподілені по 3 зонах доступності) — мають доступ до Internet Gateway та використовуються для зовнішніх ресурсів (напр. Load Balancers).
- 3 Приватні підмережі — ізольовані підмережі для баз даних чи бекенд-сервісів. Доступ до інтернету (для оновлень тощо) реалізовано через NAT Gateway.

### 3. ecr

Створює приватний реєстр Docker-образів (Amazon Elastic Container Registry):

- Налаштовано автоматичне сканування образів на вразливості при кожному пуші (scan_on_push = true).
- Додано базову політику життєвого циклу (Lifecycle Policy) для автоматичного видалення старих образів (зберігає лише 10 останніх), щоб не переплачувати за зберігання.

## 🚀 Інструкція із запуску (Step-by-Step)

УВАГА (Проблема "курки та яйця"): Оскільки віддалений бекенд налаштовується в S3 бакеті, який ми самі ж і створюємо, перший запуск потрібно виконати з локальним стейтом.

Крок 1: Тимчасово закоментуй бекенд
Відкрий файл backend.tf та повністю закоментуй весь блок terraform { backend "s3" { ... } }.

Крок 2: Локальна ініціалізація та деплой бакета
Виконай ініціалізацію проєкту та створи ресурси (включаючи S3 та DynamoDB):

> terraform init
> terraform plan
> terraform apply
> (Введи yes для підтвердження створення ресурсів).

Крок 3: Міграція стейту в AWS S3
Тепер, коли бакет і таблиця успішно створені в AWS, розкоментуй блок у файлі backend.tf і запусти повторну ініціалізацію:

> terraform init
> Terraform виявить, що конфігурація бекенду змінилася, і запитає: "Do you want to copy existing state to the new backend?".
> Введи yes. Локальний файл стейту автоматично завантажиться в S3-бакет, а локальний .tfstate буде очищено.

## 📋 Основні команди CLI

- terraform init — Ініціалізація робочої директорії, завантаження провайдерів та модулів.
- terraform plan — Створення плану виконання (перевірка змін без їх реального застосування).
- terraform apply — Застосування змін та створення/оновлення інфраструктури в AWS.
- terraform destroy — Повне видалення всіх створених проєктом ресурсів з AWS.

## 🪵 Очищення інфраструктури

Якщо вам більше не потрібні ці ресурси в AWS, виконайте:

> terraform destroy
> (Зверніть увагу: якщо в S3 бакеті або ECR репозиторії залишаться файли/образи, Terraform може видати помилку видалення через заходи безпеки. У такому разі спочатку очистьте їх вручну через AWS Console або CLI).
